# ✅ Проблема вирішена!

## Що було не так?

Вчора HedgeDoc працював, а сьогодні показував порожню білу сторінку в браузері.

## Причина

В конфігурації Docker (`/etc/docker/daemon.json`) параметр `userland-proxy` був встановлений в `false`.

```json
{
  "iptables": false,
  "dns": ["8.8.8.8", "8.8.4.4"],
  "userland-proxy": false  ← ЦЕ БУЛА ПРОБЛЕМА
}
```

Без `userland-proxy` Docker не може проксіювати порти з Windows на контейнери в WSL2, коли `iptables` вимкнений.

## Рішення

Змінено `userland-proxy` на `true`:

```json
{
  "iptables": false,
  "dns": ["8.8.8.8", "8.8.4.4"],
  "userland-proxy": true  ← ВИПРАВЛЕНО
}
```

## Як це працює?

### Без userland-proxy (не працює):
```
Windows Browser → localhost:3000 → Docker daemon → ❌ (нічого не відбувається)
```

### З userland-proxy (працює):
```
Windows Browser → localhost:3000 → docker-proxy → Container (172.20.0.3:3000) → ✅ HedgeDoc
```

## Перевірка

Після виправлення можна побачити процеси docker-proxy:

```bash
wsl -d Debian bash -c "ps aux | grep docker-proxy | grep 3000"
```

Вивід:
```
root  307  /usr/bin/docker-proxy -proto tcp -host-ip 0.0.0.0 -host-port 3000 -container-ip 172.20.0.3 -container-port 3000
```

## Чому це сталося?

Можливо, хтось або щось змінило конфігурацію Docker, або вона була неправильно налаштована з самого початку, але працювала через кеш або інші фактори.

## Як уникнути в майбутньому?

Якщо після перезапуску Windows HedgeDoc знову не працює, просто запусти:

```
fix-docker-config.bat
```

Цей батнік автоматично перевірить і виправить конфігурацію Docker.

## Технічні деталі

### Чому потрібен userland-proxy?

В нормальних умовах Docker використовує `iptables` для маршрутизації трафіку з хоста до контейнерів. Але в WSL2 Debian `iptables` не працює через відсутність необхідних kernel модулів.

Тому ми вимкнули `iptables` і використовуємо `userland-proxy` - це програма, яка працює в user space і вручну проксіює TCP/UDP трафік між хостом і контейнерами.

### Альтернативи

1. **Використовувати Docker Desktop** - він автоматично налаштовує все правильно
2. **Встановити kernel модулі для iptables** - складно в WSL2
3. **Використовувати host network mode** - не підтримується в WSL2
4. **Використовувати userland-proxy** - ✅ наше рішення
